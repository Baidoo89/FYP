# Defence-Day Checklist

## The day before

- [ ] Rehearse the slide presentation twice with a 10-minute timer.
- [ ] Rehearse the four-minute safe demonstration once.
- [ ] Rehearse the extended workflow once, then reset with `npm run defence:prepare`.
- [ ] Confirm the report, slides, and backup PDF open correctly.
- [ ] Charge the laptop and pack the charger, mouse, HDMI adapter, and a USB backup.
- [ ] Store offline copies of the deck, report, and key screenshots.

## Sixty minutes before

- [ ] Connect to power and disable sleep, pop-ups, and notification banners.
- [ ] Confirm the projector resolution and keep browser zoom at 100 percent.
- [ ] Run `npm run defence:prepare`.
- [ ] Run `npm run defence:check`, `npm run db:health`, and `npm run defence:live-check`.
- [ ] Confirm `http://localhost:3000/api/health` is healthy.
- [ ] Open the slide deck, report, login page, and fallback screenshots.
- [ ] Close personal tabs, chat applications, email, and source files containing secrets.
- [ ] Confirm the six account credentials in `docs/final-demo-walkthrough.md`.

## Five minutes before

- [ ] Start on Slide 1 in presentation mode.
- [ ] Keep water nearby and the mouse pointer off the main content.
- [ ] Take one slow breath before the first sentence.
- [ ] Remember the boundary: decision support, not automatic promotion.

## During questions

- [ ] Listen to the whole question.
- [ ] Answer in one sentence before explaining.
- [ ] Point to implementation or report evidence.
- [ ] Acknowledge limitations directly.
- [ ] Never invent a feature, result, sample size, or policy rule.
- [ ] Ask for the question to be repeated if it is unclear.

## Three facts to protect

1. Criteria Score 100/100 means verified core evidence completeness, not academic quality.
2. Submitted application and Pending documents are compatible states; HR verification happens later.
3. HOD and Dean share one prototype permission set but have separate organisational scopes; sequential HOD-then-Dean routing is future work.

## Emergency fallback

1. Stop live mutations.
2. Open Benjamin's completed application or the slide screenshots.
3. Explain the workflow from the recorded status history.
4. Continue the defence; do not troubleshoot code in front of the panel.

## Final sentence

> The system standardises and documents the promotion process while preserving the judgement and authority of the university's human decision-makers.
